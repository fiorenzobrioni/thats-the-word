# That's The Word's Baseline Profile (PLANNING.md §11 Phase 8, §15 "Phase 8").
#
# The code a player meets in the first seconds and in every game: the start, the first run (the one
# launch no profile of the phone's own can help), the start page and the game page, with what they
# stand on (the engine, the words' reader, the data, the design system,
# Hilt's graph). AGP compiles it into the APK (assets/dexopt/baseline.prof), R8 rewrites it to the
# minified names, and androidx.profileinstaller (merged through Compose) hands it to ART at the
# install, so these methods run compiled from the first launch instead of interpreted until the
# phone's own profile catches up, days later.
#
# Written by hand, in the format's own wildcards (`**` any packages, `*` one segment), because the
# generator needs a phone or an emulator: a rule names a package, never a class, so a class added
# or renamed stays covered. The libraries' own profiles (Compose, Room, Navigation, DataStore)
# arrive with them. The pages a player opens now and then (Settings, Your data, the notebook, the
# progress) are left to ART, as is the home-screen card, which Glance draws in the
# background.
#
# `ProfileRulesTest` checks that every package named here still holds code.
